**Goal:** 会议域落地——PORT 部分（预订 CRUD/会议面板/纪要/表单/入口/公告卡片）对齐 RN；GREENFIELD 部分（Agora 原生 RTC 会议房间/浮窗/横屏）按 AA 既有决策新建。RN 的"会议"本体是 WebView H5（RTC 在 H5 内），AA 用原生替换——RN 可移植的是入口/线缆/UI 逻辑，不是 RTC（调研报告 §1.4 VERDICT）。

**Architecture:** 双层——(a) PORT 层：会议预订/纪要数据全部住在房间公告（chats.announcement(s)，meetingRoomBookRecord/meeting 字段，AA RoomAnnouncements.kt 已备好数据面），CRUD 走 meetingRoomBook 等 6 接口；(b) GREENFIELD 层：Agora RTC 引擎封装 + 会中 UI + 会议状态机（对照 RN meetingSessionStore 的 phase 语义但砍掉 WebView 桥）。悬浮窗原生三文件 RN 有现成 Kotlin/Java 近乎照抄。

**Tech Stack:** 既有栈；RTC = `io.agora.rtc:full-sdk:4.x`（Agora 原生 Android，Maven Central；版本 T7 spike 时核对最新 4.x 稳定线）；浮窗 = 前台服务 + TYPE_APPLICATION_OVERLAY（RN 现成实现移植）；横屏 = Activity.setRequestedOrientation 三触发源。

## Global Constraints

- **双源 URL 陷阱（坑 1/2）**：入口常量 MEETING_HOME_URL 只当形状标记——实际加载恒为 `${serverUrl}/AntMeeting/`（尾斜杠必须）；cookie 鉴权仅同源生效（PORT 层残留此逻辑处——InAppWeb 移交分支——不得照抄常量域）
- **BackHandler 相位陷阱（坑 4）**：preheating/minimized 不吞返回键；会中返回 = 离开确认；RN 两次回归记录在案
- **互斥不对称（坑 6）**：语音任意非 idle 阻塞会议；会议仅 inMeeting/minimized 阻塞语音（preheating 不算）——方向不能抄反；AA 现无 M10 语音，会议侧规则先落（M10 对接时对侧补）
- **悬浮窗权限降级链（坑 7）**：无 canDrawOverlays → 仅前台服务通知+toast 不 crash；API 34+ SPECIAL_USE FGS 类型；渠道对齐 M6-T2 渠道桩勿重复建
- **腾讯会议记录去留裁定**：保留外跳（wemeet:// scheme + https 外开），与 RN 行为一致；createTxMeeting=true 服务端代建
- **手动会议号必填对（坑 11）**：!createTxMeeting 时 meetCode+meetUrl 都必填
- RTC 层 greenfield：**token/appId 来源是最大未知**（RN wire 无此接口）——T1 spike 裁定（见 Open Questions）；staffService/AntMeeting-WebView 预热随原生替换整体作废（与 M6 注记对账）
- 纯函数优先 TDD（payload 构建/校验/URL 工具/分组排序全 TDD）；文案 i18n（meeting_* 键核对补充）；提交中文
- 用户验收分工同前；**Agora 控制台 AppId = 用户域依赖**（计划批准时请确认账号可用）

## Open Questions（T1 spike 裁定，影响 T7 形态）

1. **RTC token/appId 来源**：meetingRoomBook 返回体是否含入会凭证（RN 不消费）？服务端是否有 token 接口？——T1 用真实环境探测（抓 meetingRoomBook 响应 + 探测常见 token 端点）；若无接口：测试期走 App Certificate 无 token 模式打通，生产 token 接口列为服务端需求交用户。
2. **与老 H5 会议互通**：若服务端仍运行 H5 会议且需互通——同频道互通需相同 AppId+token 体系；裁定默认"不要求与 H5 互通"（原生替换）。
