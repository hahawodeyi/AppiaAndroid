### 1.2 三类"会议"的区分（判定）

- **(a) AntMeeting 预热 WebView（RN 的"会议"本体）**：应用内会议 = 内嵌 WebView 加载 H5 SPA（Vite 部署于 `${serverUrl}/AntMeeting/`，带尾斜杠，`MeetingWebHost/index.tsx:22-25`）。RTC 全部发生在 H5 内部——证据：`MeetingWebHost/index.tsx:38` 注释"预热 WebView 虽会连带触发 WebRTC/Agora init，但与 RN 首屏并行不互斥"，即 web 侧自己初始化 Agora（Web SDK），RN 原生层零参与。鉴权靠 Cookie 注入（`MeetingWebView/index.tsx:58-83`：authToken/userId/enterpriseId cookie，`injectMeteor` 仅当 `urlsSameOrigin(url, serverUrl)`）。
- **(b) 腾讯会议外链**：完全外跳不集成。`InAppWebScreen/index.tsx:378-385`：`meeting.tencent.com` http 链接 → `Linking.openURL` 系统打开；`wemeet://` → `return false` 交系统。审批卡可拼 `wemeet://page/inmeeting?meeting_code={code}` 拉起腾讯会议 App（`useApprovalCardActions.ts:126-128`、`lib/approval/approvalLink.ts:3-4`）。预订表单 `createTxMeeting=true`（新建默认 true，`MeetingFormScreen/index.tsx:116`）由**服务端**代建腾讯会议，记录回填 `tencentMeetingId`（`types/meeting.ts:49-50`）。
- **(c) 原生 RTC 会议室**：**不存在**。RN 无任何原生会议房间 UI；`react-native-agora` 只被 `src/services/voice/`（M10 语音）引用（见 §5）。

### 1.3 WebView 桥协议（verbatim，`lib/meetingBridge/types.ts`）

web → app（`postMessage(JSON.stringify)`，`parseMessage.ts` 严格校验字段类型）：
- `{type:'meeting:minimize'}`
- `{type:'meeting:state', data:{title:string, meetingNumber:string, duration:string, participantCount:number, isMuted:boolean, page:'home'|'in-meeting'}}`
- `{type:'meeting:ended'}`
- `{type:'meeting:kicked', reason?:string}`
- `{type:'meeting:tap'}`
- `{type:'meeting:orientation:landscape'}` / `{type:'meeting:orientation:portrait'}`
- `{type:'meeting:header:visible', visible:boolean}`
- `{type:'meeting:page', page:'home'|'in-meeting'}`（首次上报 = web bootstrap 完成 = webReady）

app → web（`injectJavaScript` 派发 `window` MessageEvent，`postToWeb.ts:23-26`）：
- `{type:'meeting:restore'}`、`{type:'meeting:queryState'}`
- `{type:'meeting:pause-audio', requestId}` / `{type:'meeting:resume-audio', requestId}`
- `{type:'meeting:request-leave'}`
- `{type:'meeting:join', meetingNumber}`（SPA navigate 到 `/{num}` 自动入会，不换 source 不重载）

### 1.4 VERDICT：M8 是 PORT 还是 GREENFIELD？

**GREENFIELD（RTC 层）+ PORT（周边线缆）。**
RN 的"会议"没有原生实现：入会 = WebView H5（H5 内部自带 Agora Web SDK），音视频/共享/成员全在 web。AA 已决策用 Agora 原生 SDK（memory 锁定），因此：
- **必须新建（greenfield）**：会议房间 UI（视频宫格/控制条/共享视图/成员）、Agora RTC 引擎接入、RTC token 获取、横屏会中布局。
- **可从 RN 移植（port）**：入口点、预订 CRUD wire（§2.3）、会议面板/纪要（数据全部来自房间公告，AA `RoomAnnouncements.kt` 已保留 meeting JsonObject 原文）、浮窗原生模块（RN 的 Kotlin/Java 可近乎照抄，§4）、横屏策略、互斥规则、表单校验。
- WebView 预热桥协议对 AA 无直接用处（不再有 H5），但它是**会议状态机的规格说明**（phase/webReady/state 载荷/离开确认语义），M8 状态机可对照设计。

## 6. 坑清单

1. **双源 URL 陷阱**：入口常量 `MEETING_HOME_URL=https://meeting.appia.cn/AntMeeting`，而预热/实际 source 恒为 `${serverUrl}/AntMeeting/`（`openAntMeetingWeb.ts:51-69`）。常量域只当"形状标记"，真正加载的是 serverUrl 源——Cookie 注入仅对 `urlsSameOrigin(url, serverUrl)` 生效（`MeetingWebView:62`）。AA 若照抄常量直接加载 meeting.appia.cn 会丢鉴权。
2. **预热 URL 必须带尾斜杠** `${serverUrl}/AntMeeting/`（Vite base 部署匹配，`MeetingWebHost:22-25`），否则命中 base-mismatch 警告页。
3. **webReady 门**：只有 web 首次上报 `meeting:page` 后才可 postMessage 入会；预热入会不得换 source（重载即失效，`openAntMeetingWeb:57-61` + `MeetingMinimizeShell:112-120`）。greenfield 后此坑消失，但"就绪才投递 join"的状态机语义值得保留。
4. **BackHandler 相位陷阱**：preheating/minimized 必须 `return false` 交还导航，否则全 App 返回键/左滑失效（`MeetingMinimizeShell:79-100`，注释记录 2026-09-30、2026-10-07 两次回归）。会中返回≠退出：`page==='in-meeting'` → 发 `meeting:request-leave` 走 web 离开确认面板（:57-77）。AA 原生版对应：会中返回弹离开确认，列表态才拆会。
5. **WebView 渲染进程崩**：`onRenderProcessGone` → toast `meeting_connection_lost` + `endMeeting` + return true（`MeetingWebView:156-160`）；对比 InAppWebScreen return false 防崩溃循环——两种策略都存在，别混。
6. **互斥不对称**：语音任意非 idle 阻塞会议；会议仅 inMeeting/minimized 阻塞语音（preheating 不算"进行中"，§3）。AA 两侧都要实现且方向不能抄反。
7. **悬浮窗权限降级链**：无 `canDrawOverlays` → 仅前台服务通知 + toast，不 crash（`MeetingForegroundService.kt:39-49`）；API 34+ SPECIAL_USE FGS 类型必须声明；渠道 `meeting_active` 需与 AA M6-T2 渠道桩对齐（勿重复建）。
8. **会议附件显隐门槛**：`Appia_Meeting_Enable !== false`（默认开）+ 非 omnichannel + `usernames.length>1`（单聊隐藏）（`canShowMeetingAttachment.ts:12-17`）；AA registry 已有该键（`ServerSettingRegistry.kt:147`）。
9. **加入解析次序与腾讯号回退**：`meetUrl` 优先，其次 `meetCode ?? tencentMeetingId`（`RoomMeetingScreen:148`）——腾讯号也会被喂给 `buildAntMeetingUrlFromCode` 拼成 `${serverUrl}/AntMeeting/{tencentId}`；若该记录无 meetUrl，行为取决于 H5/服务端能否识别腾讯号。M8 原生版需决定：Tencent 记录继续外跳 wemeet，还是也走 AntMeeting。
10. **公告存储形态不固定**：`chats.announcement(s)` 可为纯文本/JSON/双编码/`` 分隔嵌入文件（AA `RoomAnnouncements.kt:8-11` 已移植）；meeting 字段必须保留 JsonObject 原文等 M8 消费。
11. **手动会议号必填对**：`!createTxMeeting` 时 meetCode 与 meetUrl **都**必填（`buildMeetingPayload.ts:57-58`），仅填一个会被打回。

## 7. 落地建议（供 plan 参考，非结论）

### 7.1 Agora SDK（Android 原生）

- RN 走 `react-native-agora@4.5.4`，其封装的原生层是 Agora RTC SDK 4.x。AA 直接引原生坐标：`io.agora.rtc:full-sdk:4.x`（Maven Central；具体最新稳定版 plan 时核对 https://docs.agora.io 的 Android SDK release note，4.5.x 系列为当前 4.x 稳定线）。仅音频可考虑 `full-sdk` 降配或 `audio-sdk`——M8 含视频/共享则 `full-sdk`。
- 需要可互操作 RN H5 老会议的话，注意 channel profile/编码参数与 web 端一致性——但 AA 决策是原生替换，是否还要与老 H5 互通属于 plan 决策点（**待确认**：服务端是否仍有 H5 会议；若有，同频道互通需相同 AppId+token 体系）。

### 7.2 开放问题（plan 必须先确认）

1. **RTC token/appId 来源**：RN 线缆里没有任何 Agora token 接口（鉴权藏在 H5 后端会话里）。原生入会需要 appId + token（或 App Certificate 无 token 模式）。`meetingRoomBook` 返回体是否含入会凭证未知（RN 不消费）。需要抓服务端文档/后端确认，这是 M8 最大未知。
2. AA `InAppWebScreen.kt:297` 把 "AntMeeting 预热" 记在 M10 名下——原生 M8 后 WebView 预热整体删除，plan 里对账。
3. 腾讯会议记录（`createTxMeeting=true` / `tencentMeetingId`）在 M8 里的去留：建议保留外跳（wemeet scheme + https 外开），与 RN 行为一致。

### 7.3 模块布局草案

- `core/meeting`：wire client（`meetingRoomBook` 等 6 个接口 + IMeeting/IMeetingRoom/IMeetingSummary 模型 + payload 构建/校验移植 `buildMeetingPayload`）。AA `RoomAnnouncements.kt` 已备好数据面。
- `feature/meeting`（大半 PORT）：MeetingPanelScreen（=RoomMeetingScreen：bookings/minutes 双 tab + 加入/编辑/删除）、MeetingFormScreen（表单 + 周期 + 会议室时间轴 `MeetingRoomSection/PickerModal/TimelineRow`）、RoomInfo 会议行接通、三个全局入口（+ 菜单/抽屉/附件）、MeetingSummaryDetailScreen。
