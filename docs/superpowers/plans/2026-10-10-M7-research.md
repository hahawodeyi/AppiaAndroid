### 3.4 SSE wire（`lib/ai/aiStream.ts`）

- **POST SSE**：`react-native-sse` 的 EventSource，`method:'POST'`，headers `content-type: application/json` + **小写** `x-auth-token` / `x-user-id`；body `{prompt, stream:true, rid, agentUserId?}`（:24-39）。
- chunk 解析 `parseStreamData`（`lib/ai/streamData.ts:11-21`）：每条 `data:` 为 JSON `{type?: 'START'|'EVENT'|'MESSAGE'|'FINISH'|'DONE'|'ERROR', text?, content?, error?}`；非 JSON 整体作 `{raw}`。取文本次序 `text ?? content ?? raw`（aiStream.ts:70）。
- 终止语义：`data.error` 或 `type==='ERROR'` → onError；`type==='FINISH'|'DONE'` → onFinish；error/close 事件 → 'network'/finish。
- **大坑**（aiStream.ts:41-51 注释）：react-native-sse 在连接 DONE 后 `_pollAgain` 会**重开连接重发 body** → 必须主动 `es.close()` 单次化（terminate 守卫）。AA 用 OkHttp 自实现时天然无此坑，但「FINISH 后服务器可能不关连接」仍需处理（读 body 至流结束/收到 FINISH 即止）。
- AA 无 okhttp-sse 依赖（`gradle/libs.versions.toml:49` 仅 okhttp 5.3.0）；SSE 用 OkHttp 流式 body 手写即可（M6 报告所述 SSE-capable 栈即此）。

## 6. 坑清单（按移植风险排序）

1. **todo 双计数源不同步**：抽屉徽标 = REST total（mutation 后才失效，`useTodoListQuery.ts:70-77`）；会话红点 = DDP subscription `todoCount`。完成待办后抽屉数字即时变，红点等 DDP——RN 就存在两源短暂不一致，别试图用单一源「修」齐。
2. **set/finish 的 status 语义不对称**：设待办发 `status:1`（RoomScreen:835），消息回流却是 `status:0` 才算「进行中」（RoomMessageRow:105、messageActions:165）；完成发 `-1`。发送值与显示值不同是服务端约定，照抄勿"修正"。
3. **设待办本地不写 appiaTodo**：靠 DDP stream 推回更新；若 AA 消息流处理漏 `appiaTodo` 字段的 update 分支，长按菜单状态会不刷新（`MessageUpsert.kt:94` 已处理 upsert，需确认 stream changed 路径同样走它）。
4. **react-native-sse 的 `_pollAgain` 重连重发 body**（aiStream.ts:41-51）：RN 用 terminate 单次化。AA 手写 OkHttp SSE 无此坑，但**收到 FINISH/DONE 后必须停止读取**，别等服务器关流（RN 注释暗示服务器 DONE 后可能不主动关）。
5. **AI 流式文本只活在组件 state，持久化靠客户端回写 `bot.saveAIMessage` + DDP 回流同 id 替换**（AgentLoadingMessage:104-132 + RoomMessageList:166-172）：双端兜底（真实消息到达 clear / 15s 超时强清）缺一即卡死「串行驱动 + 停止按钮」。错误路径也必须 finalize（:188-190）。
6. **槽位防闪烁不变量**：同 id 真实消息已在列表则不注入槽位（RoomMessageList:135）；`runAiTurn` 必须先 setProcessing 再 await clear（runAiTurn:31-33），顺序反了会覆盖槽位中止上一条流。
7. **prompt 剔除 @bot 文本**：发 `.bot` 的 prompt 不能含 `@xxx.bot` 字样（parseBotMentions.ts:37-43），且附件有专用模板串（image-url/file-proxy）。漏掉即 bot 收到脏 prompt。
8. **worktable_config 是裸 fetch**（fetchWorktableConfig.ts:15-16）：不走 IM sdk/auth 头；配置内相对 url/icon 需补 server 前缀（normalizeWorktableGroups:29-38）。放 Retrofit 时注意别套 AuthInterceptor。
9. **泛微 Android 是三件套而非一件事**：请求头 `Weavertoken`（首载）+ cookie 写入 + sessionStorage 防循环 reload（InAppWebScreen:330-352）+ XHR/fetch 劫持补丁（buildInjectedScripts:88-120）——AA WebView 的 `shouldOverrideUrlLoading`/`onPageStarted` 时序与 RN `injectedJavaScriptBeforeContentLoaded` 不同，cookie+reload 那套要靠 `onPageFinished`/`doUpdateVisitedHistory` 重现，且 reload 防循环 key（`hasReloaded_<url>`）必须保留。
10. **返回决策链比「canGoBack 就 goBack」长**：chat-gpt source、`/approve/list|/error|/40[035]` 段、根页比较（origin+hash 去=query）、antagent 两 URL 强制 pop（resolveInAppWebBackAction.ts:3-8,39-79）。漏分支 = 用户困在 H5 错误页。
11. **小写 header**：SSE 用 `x-auth-token`/`x-user-id`（aiStream.ts:35-36），与 REST `X-Auth-Token` 大小写不同（服务端不敏感，但对齐可省排查）。
12. **待办完成要双写**：POST 成功后还需清本地消息 `appiaTodo`（clearMessageAppiaTodo，消息未落库 catch 忽略）；AA 若只发 POST 不清库，房间内消息待办样式不消失（列表页由 invalidate 兜住，房间内不会）。
