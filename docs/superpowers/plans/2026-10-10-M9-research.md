## 2. 凭证 RSA-OAEP 加密传输（最高优先）

### 2.1 加密实现（`src/services/mail/mailCredentialTransport.ts` 全文 81 行）

- 库：`react-native-quick-crypto` 的 **WebCrypto `subtle`**（v1.1.5），非 jsencrypt。
- 密钥来源：**服务器下发**，`GET /accounts/credential-public-key` 返回：

```json
{ "algorithm": "RSA-OAEP", "hash": "SHA-256", "publicKey": "-----BEGIN PUBLIC KEY-----...", "keyVersion": 1 }
```
（mailCredentialTransport.ts:4-9；mailApi.ts:112-113）

- 导入：`subtle.importKey('spki', pem 去头尾 base64 解码, { name: 'RSA-OAEP', hash: 'SHA-256' }, false, ['encrypt'])`（:39-45）。
- 加密：`subtle.encrypt({ name: 'RSA-OAEP' }, key, utf8(plaintext))`（:46-50）。**alg 里不带 hash——hash 在 importKey 时绑定**；WebCrypto RSA-OAEP 语义 = OAEP-SHA256 + MGF1-SHA256。
- 输出：**密文 ArrayBuffer → base64 字符串**（:32-33, :51）。
- **只加密密码**。email 明文随包发送。线上格式：`{ "email": "<明文>", "encryptedPassword": "<base64 密文>" }`（:72-80）。keySize 由服务器 PEM 决定，客户端不传。
- 公钥内存缓存（模块级 `cachedPublicKey` + in-flight promise 去重，:16-17, :54-70）；无本地持久化、无 keyVersion 失效逻辑（缓存不过期）。

### 2.2 凭证录入/存储

- 录入：仅 MailAccountSetupScreen。email 自动预取（user.emails[0]；无则手输，index.tsx:50-51, 152-183），密码 `secureTextEntry`（:186-202）。**无 IMAP/SMTP host/port 手工配置**——服务器端按 email 域自动推断。
- 本地存储：**密码不落盘**。MMKV 只存 pinned/lastVisitAt/未读数/预览（mailChannelStore.ts:37-42）。凭证只在服务端。

### 2.3 Wire 逐字（bind/test）

```
POST {server}/mail/api/accounts/test-connection     ← 先测试
POST {server}/mail/api/accounts                     ← 绑定
两者 body 完全相同（mailApi.ts:120-130）:
{ "email": "user@x.com", "encryptedPassword": "<base64 RSA-OAEP(pwd)>" }
成功 → MailAccount { id, email, active, lastSyncAt?, createdAt }
```

节流保护：HTTP 429 或 message 含 `too many login attempts` / `too frequent` → 专用 toast（mailApi.ts:35-39, SetupScreen:98-101, 123-125）。

## 3. 收件箱/详情/撰写 wire

### 3.0 Client 基座（mailClient.ts）

- 基址：`resolveMailApiBase = server + '/mail/api'`（mailApiBase.ts:1-4）。
- 鉴权：每请求带 `X-Auth-Token` + `X-User-Id`（RocketChat 同款头），并从 cookie store 组 `Cookie` 头、回写 Set-Cookie（mailClient.ts:76-82, 103-146）。
- 401 → `POST /auth/refresh`（cookie 会话）→ 原请求重试一次（:158-167）。
- 会话引导 `bootstrapMailSession`（mailApi.ts:71-107）：`GET /accounts` 401 → `POST /auth/appiaim-exchange` body `{ appiaimUserId, appiaimToken, email, name?, username? }` → 重试；403 / setup-required → 返回 `[]` → 导航去绑定页。

### 3.1 列表

```
GET  /accounts                                          → MailAccount[]（取 accounts[0] 为主账户）
GET  /accounts/:id/folders                              → { folders: [{ path, name, specialUse?, flags[] }] }
GET  /accounts/:id/messages?folder&page&pageSize&unreadOnly&threadId&conversationId
                                                        → { messages[], total, page, pageSize }
GET  /accounts/:id/messages/search?q&folder&page&pageSize
POST /accounts/:id/sync        body {folder?}           → { syncLogId, status, newCount }   ← 下拉刷新触发
DELETE /messages/:id                                    → { permanent, trashFolder? }
```
- 分页：`MAIL_PAGE_SIZE = 30`（lib/mail/constants.ts:5），`onStartReached` 向上加载更旧（列表**升序、 newest 在底部**，类聊天，MailChannelScreen:674-678）。
- 文件夹：specialUse 标记（`\Inbox/\Sent/\Drafts/\Trash/\Junk`）+ path 正则兜底映射 label（mailFolderUtils.ts:13-28）；IMAP Drafts 文件夹隐藏，用虚拟 `__drafts__` 文件夹装服务端草稿（constants.ts:3, :37-43）；`Virus Items` 过滤。
- 未读：服务端 `message.read` 标记列表行；**无显式 mark-read 端点**（打开详情靠服务端隐式置读）。channel 角标是纯客户端启发：`lastVisitAt` 之后 INBOX 第一页（pageSize=100）内 receivedAt 计数（mailApi.ts:314-338）；进列表页 `markChannelVisited()` 清零。
- 草稿列表：`GET /drafts` 全量 → 客户端按 accountId 过滤 + updatedAt 升序（MailChannelScreen:277-291）。

### 3.2 详情 + 附件

```
GET /messages/:id                        → MessageDetail（归一化见坑#3）
GET /messages/:id/attachments/:part      → 二进制流（X-Auth 头下载）
GET /accounts/:id/messages/:id/thread    → { messages: [{id,from,fromName,subject,receivedAt,bodyText?,bodyHtml?}], subject? }
```
- id 归一化：列表/卡片 id 带 `mail-` 前缀，detail/attachment URL 前先剥掉（normalizeMailMessageDetail.ts:20-21）。
- 附件下载：RNFetchBlob → `DocumentDir/mail_attachments/{msgId}_{part}/{sanitized name}`，命中缓存直接用；超时 `30s + size/512KB×1s`，上限 120s（downloadMailAttachment.ts:24-53, mailAttachmentLimits.ts:19-22）。
- 预览策略（mailAttachmentLimits.ts:1-17 + MailDetailScreen:273-321）：>25MB 仅下载；5-25MB 确认后预览；≤5MB 直接预览。image→ImagePreview、video→UrlMediaPreview、pdf→DocPreview、其余 FileViewer open-with（openMailAttachment.ts:19-69）。
- 下载到设备：Android 走外部 Downloads 目录 + DownloadManager 通知（saveMailAttachmentToDevice.ts:46-62）。
- 删除：Trash 文件夹内 → 永久删除二次确认文案（mailFolderUtils.ts:30-35, MailDetailScreen:199-216）。
- 线程加载三级降级：thread 端点 → threadId/conversationId 查列表（pageSize=100）→ 仅锚点消息（mailThread.ts:76-119）。

### 3.3 撰写/发送

```
POST /accounts/:id/send                                  ← 新写
POST /accounts/:id/messages/:id/reply                    ← 回复
POST /accounts/:id/messages/:id/forward                  ← 转发
POST /accounts/:id/messages/:id/reply-draft              ← 转发先建服务端草稿（失败降级本地预填）
POST /accounts/:id/messages/:id/forward-draft
POST /drafts            PUT /drafts/:id    GET /drafts[/:id]    DELETE /drafts/:id
POST /drafts/:id/send
GET  /contacts/search?q                                 → ContactSuggestion[]（name/email/department/phone/source）
```

SendMailRequest（types/mail.ts:77-85）：
```json
{ "to": [], "cc": [], "bcc": [], "subject": "",
  "bodyText": "...", "bodyHtml": undefined,
  "attachments": [{ "filename": "a.pdf", "contentType": "application/pdf", "content": "<纯 base64，无 data: 前缀>" }] }
```
- **附件不复用 M3 upload 链**：DocumentPicker 选文件 → RNFetchBlob 读 base64 → **JSON 内联**。上限 10 个 / 总 25MB（mailComposeAttachments.ts:5-6）。
- 正文：**纯文本 only**（multiline TextInput → bodyText；bodyHtml 从不设置，MailComposeScreen:679-687, :258-268）。转发预填也是 bodyText。
- 回复预填：to=from、cc 空；replyAll 把 from+to+cc 去重去自己后全进 `to`；`Re:`/`Fwd:` 前缀去重（replyRecipients.ts:14-47, mailComposeForm.ts:25-30）。
- 联系人联想：To 聚焦 + ≥2 字符 + 300ms debounce（MailComposeScreen:58, 233-256）。
- 草稿：发送前若 dirty 先 persistDraft 再 `POST /drafts/:id/send`（:363-369）；离开拦截 beforeRemove + dirty 确认（:522-532）。

### 3.4 推送/刷新 + 账户设置

- **推送**：DDP `stream-notify-user` 事件 `<uid>/mail.updated`，payload `{ accountId, folder, newCount, at? }`（mailUpdatedHandler.ts:22-45；订阅挂在 session.ts:254-259）。仅 INBOX 容错匹配（剥 `\\` 前缀+大写，:16-20）→ 角标 +n + 刷新预览。**无轮询定时器**；刷新=下拉显式 sync。
- **账户设置**：⚠️ RN 没有独立账户设置页。Setup 页只做 绑定+测试连接+引导图（`{server}/mail/guide-step1.png|guide-step2.png`，加载失败隐藏，SetupScreen:37-38, 253-274）。**无解绑/删除账户、无签名、无拉取窗口、无多账户管理**（grep 证实无 deleteMailAccount/signature）。M9 的「账户设置」= 绑定页。

## 5. 坑清单（RN 实证）

1. **Android RSA-OAEP MGF1 陷阱（最重要）**：WebCrypto RSA-OAEP-SHA256 = OAEP-SHA256 + **MGF1-SHA256**。Android `Cipher "RSA/ECB/OAEPWithSHA-256AndMGF1Padding"` 在部分 provider 下 MGF1 默认 SHA-1，与服务器密文不互认。必须显式 `OAEPParameterSpec("SHA-256","MGF1",MGF1ParameterSpec.SHA256,PSpecified.DEFAULT)`（证据：RN 端 importKey 绑定 SHA-256，mailCredentialTransport.ts:39-50）。
2. **公钥缓存无失效**：模块级缓存永不刷新，`keyVersion` 字段被忽略（mailCredentialTransport.ts:16-17, 54-70）；服务器换钥会全量绑定失败。AA 建议按 keyVersion 缓存。
3. **详情字段多态**：`attachments|attachmentList` × `part|partId|partNumber` × `filename|name` × `contentType|mimeType` × `size|bytes` 五组别名归一化，part 为空/无文件名的附件直接丢弃（normalizeMailMessageDetail.ts:3-48）。AA 解析需同样容错。
4. **id 前缀**：列表消息 id 带 `mail-` 前缀，detail/attachment URL 必须剥掉（normalizeMailMessageDetail.ts:20-21）。
5. **节流**：绑定/测试连接被服务器限流（429 或 `too many login attempts`/`too frequent`），需专用 toast 而非通用失败（mailApi.ts:35-39）。
6. **401 引导链**：`GET /accounts` 401→exchange→重试；**403 =「邮件未开通」静默返回空**，不能当错误弹（mailApi.ts:71-107）。
7. **INBOX 大小写/前缀**：IMAP 可能返回 `Inbox`/`\\Inbox`，推送事件与 label 判断都要归一化（mailUpdatedHandler.ts:15-20）。
8. **未读数启发式有天花板**：只扫 INBOX 第一页 100 条（fetchMailUnreadCount:327-333），积压 >100 少算；且无 mark-read 端点——已读态完全依赖服务端在 GET detail 时置读，列表页返回后靠重拉刷新。
9. **列表是聊天式升序**：旧→新、锚定底部、`onStartReached` 翻旧页（MailChannelScreen:674-678, 94-110）；常规「邮件列表倒序+翻下一页」的直觉实现会对不上验收。
10. **HTML 渲染无 sanitize**：详情用 react-native-render-html v6.3.4 直接渲染 bodyHtml（MailDetailScreen:370-381），style/script 标签只在「线程纯文本预览」里被 regex 剥掉（mailThread.ts:56-65）。Android 侧 WebView 必须禁 JS。
11. **草稿是虚拟文件夹**：IMAP Drafts 目录被隐藏，草稿走服务端 `/drafts` 全量拉取客户端过滤；草稿视图删光最后一条要弹回 INBOX（MailChannelScreen:495-502, mailFolderUtils.ts:37-43）。
12. **附件 JSON 内联**：25MB 文件 ≈ 33MB base64 字符串整包进 JSON body——内存峰值明显（mailComposeAttachments.ts:66-84）。Android 需流式读盘直 encode，避免整文件 byte[]。
13. **回复全部进 To**：replyAll 不填 cc（replyRecipients.ts:29-47），验收对照时别按「cc 有值」断言。
14. **Cookie 会话耦合**：mail client 手动组 Cookie 头（exchange 建立的会话），AA 的独立 mail OkHttp client 需自带 CookieJar（mailClient.ts:76-82, 124-127, 142-146）。

## 6. 落地建议

### 模块布局（对齐 AA 现有分层）

```
core/mail/
  MailApi.kt            — 端点封装（Retrofit 或复用 OkHttp 栈），base = {server}/mail/api
  MailAuthInterceptor.kt — X-Auth-Token/X-User-Id + CookieJar + 401 refresh 重试
  MailCredentialCipher.kt — javax.crypto RSA-OAEP（显式 OAEPParameterSpec SHA-256/MGF1-SHA256）+ 公钥按 keyVersion 缓存
  MailModels.kt          — types/mail.ts 全量映射（含归一化别名）
feature/mail/
  MailAccountSetupScreen / MailChannelScreen(+FolderSheet) / MailDetailScreen /
  MailComposeScreen / MailThreadScreen
  MailChannelViewModel   — 内存态列表（RN 无本地邮件 DB，M9 同样不需要 Room 表）
  MailBadgeStore         — pinned/lastVisitAt/未读/预览 → DataStore（对应 MMKV store）
  mailUpdatedHandler     — 挂到现有 stream-notify-user 分发
```

### 技术选型

- **加密：`javax.crypto` 内置足够，不引 BouncyCastle**——RSA/ECB/OAEP + 显式 OAEPParameterSpec 即与 WebCrypto 对齐。落地第一步写一个固定测试向量互操作测试（server 公钥加密 → 服务器可解，或与 RN 端密文比对）。
- **正文编辑：纯 `TextField`**（RN 即纯文本，bodyText only）。10tap WebView 不需要。
- **HTML 邮件阅读：Android WebView（JS 禁用）**最省事且保真；render-html 无 Android 对应物，TextView Html.fromHtml 会丢 CSS 布局。
- **附件预览复用** DocPreview/ImagePreview/VideoPreview；下载用 OkHttp 流式 + MediaStore Downloads。
- **未读/角标**照抄客户端启发式（lastVisitAt + INBOX 首页 100 条扫描），含其 100 条天花板（坑#8），验收对照口径一致。
- **开关**：`Appia_Mail_Channel_Enabled` 已在 AA registry，直接接 useMailChannelEnabled 等价物。

### M9 范围提示

- 「账户设置」实为**绑定页**（email+密码+测试+绑定），RN 无解绑/删除/签名/多账户切换——计划里不要为它们排任务。
- 验收「邮件收发对照」注意：列表升序底部锚定（坑#9）、replyAll 无 cc（坑#13）、附件 JSON 内联上限 10 个/25MB。
