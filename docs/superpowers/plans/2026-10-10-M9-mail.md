# M9 邮件 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 复刻 appiaMobile 的邮件域——凭证 RSA-OAEP 加密传输（绑定/测试连接）、收件箱（聊天式升序+文件夹+同步）、详情（HTML 渲染+附件+线程）、撰写（5 模式+附件内联+服务端草稿）、推送角标（DDP mail.updated+未读启发式）。

**Architecture:** RN 邮件域完整（调研报告，非 stub）。三基座：(a) mail client 独立于 RocketSdk——`{server}/mail/api` 基址 + X-Auth-Token/X-User-Id + **CookieJar** + 401→`/auth/refresh`→重试一次 + 403=未开通静默空；(b) RSA-OAEP 凭证加密——javax.crypto 内置（无 BouncyCastle）+ **显式 OAEPParameterSpec(SHA-256, MGF1, MGF1-SHA256)**（坑 1 MGF1 默认 SHA-1 陷阱）；(c) 无本地邮件 DB——列表/角标内存+MMKV，Room 不建表。

**Tech Stack:** 既有栈；加密 = javax.crypto 内置（不引 BouncyCastle）；HTML 详情 = WebView **JS 禁用**（RN render-html 无 sanitize——Android 禁 JS 等价安全位）；正文编辑 = 纯 TextField（RN 即纯文本，10tap 不引入）；附件 = JSON 内联 base64（**不复用 M3 upload 链**——流式读盘防 25MB 峰值）。

## Global Constraints

- **坑 1（最重要）**：RSA-OAEP 必须**显式 OAEPParameterSpec("SHA-256","MGF1",MGF1ParameterSpec.SHA256)**——Android 部分 provider 的 OAEPWithSHA-256AndMGF1Padding 默认 MGF1-SHA1，与服务器密文不互认；落地第一步写固定测试向量互操作测试
- **坑 2 改进**：公钥缓存按 keyVersion（RN 永不刷新是缺陷——服务器换钥全量绑定失败；AA 按 keyVersion 缓存修正）
- **坑 6**：GET /accounts 401 → exchange → 重试；**403 = 邮件未开通静默返回空**（不能当错误弹）
- **坑 9**：列表聊天式**升序、锚定底部**、onStartReached 翻旧页——常规倒序实现对不上验收
- **坑 13**：replyAll 全进 to 不填 cc（验收对照勿按 cc 断言）
- **坑 12**：附件 JSON 内联 base64（10 个/25MB 上限）——流式读盘直 encode 防整文件 byte[] 内存峰值；**不复用 M3 upload 链**
- **坑 10**：HTML 邮件详情 WebView **JS 禁用**（RN render-html 无 sanitize——禁 JS 为等价安全位）
- **坑 5**：绑定/测试连接 429 或 `too many login attempts`/`too frequent` → 专用节流 toast
- **坑 8**：未读启发式仅扫 INBOX 首页 100 条（无 mark-read 端点——已读靠服务端 GET detail 隐式置读）；含天花板照抄
- 「账户设置」实为**绑定页**（RN 无解绑/删除/签名/多账户——不要为它们排任务）
- 纯函数优先 TDD（加密向量/payload/归一化/预填规则全 TDD）；文案 i18n（mail_* 91 键已备核对）；提交中文
- 用户验收分工同前；**邮件服务端可用 = 用户域依赖**（绑定真邮箱测试）
