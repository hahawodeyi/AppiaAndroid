# Appia 原生重写用户自测协议（M1 登录链路 + M2 会话列表/聊天 + M3 富文本消息，版本 0.4.0）

> 本文是面向自测人的操作手册。原生版（`cn.appia.im.debug`，versionName **0.4.0**）已实现 M1 全部链路（企业码验证 → 服务器列表 → SMS 登录 → 会话持久化 → 组织切换 → 登出/会话失效）、M2 全部链路（会话列表 + 房间聊天）与 M3 全部链路（富文本编辑/渲染、附件收发查看、转发、表情回应、已读回执、编辑/撤回、@提及、长按菜单）。
> 自测方法：**与 RN 版（appiaMobile）side-by-side 对照**——同一操作在两个版本各做一遍，比较表现差异。M1 链路见第二~五节，M2 见第六~七节，M3 见第八~九节。

## 一、安装步骤

APK 由开发侧交付（也可自建：仓库根目录执行 `./gradlew :app:assembleDebug`，产物在 `app/build/outputs/apk/debug/app-debug.apk`）。

```bash
# -r = 已安装时覆盖升级，保留本地数据
adb install -r app-debug.apk
```

启动：桌面点开 **Appia** 图标（debug 版）。确认版本号 0.4.0：企业码页底部页脚常驻版本行，应显示 `0.4.0`。

**与生产版共存**：debug 包名为 `cn.appia.im.debug`（生产版为 `cn.appia.im`），二者可同时安装在同一台设备，数据完全隔离，互不影响。注意 debug 版**不会**覆盖 RN/生产版的数据，需用真实账号重新登录一次。

前置条件：设备可访问真实验证环境（企业码 verify 接口走 `https://appia.cn`）。

## 二、自测清单

逐项勾选。每项标注「RN 对照点」——即与 RN 版比较时应关注什么。

### 1. 企业码验证（真码）

- [ ] 输入真实企业码 → 点「验证激活」→ 跳转登录页（短信模式）
- [ ] 输入不存在的企业码 → 弹「企业验证失败」Alert，点「关闭」可关闭并留在本页
- [ ] 不输入直接点「验证激活」→ 弹「信息不完整 / 请输入企业识别码。」

**RN 对照点**：跳转时机（RN `navigation.replace`）、Alert 标题/正文文案、loading 期间按钮禁用表现。

### 2. SMS 登录（发码 / 滑块 / 验证码）

- [ ] 输入手机号 → 点「获取验证码」→ 弹「安全验证」滑块，拖动通过 → 手机收到短信验证码
- [ ] 滑块未完成时点「获取验证码」→ 提示需先完成滑块
- [ ] 输入收到的验证码 → 点「登录」→ 进入主屏
- [ ] 输错验证码 → 失败提示（文案与 RN 比对）
- [ ] （可选）CAS SSO 入口：点「SSO 登录」→ WebView → 登录成功进主屏

**RN 对照点**：滑块弹层形态（底部弹层 vs 居中）、倒计时秒数与「重新发送」文案、验证码位数、错误文案。

### 3. 登录后占位主屏（Main）

> **0.3.0 起（M2）主屏已替换为会话列表**，本项仅 0.2.0 存档适用；「我的企业 / 退出登录」入口现位于列表右上角菜单，组织切换/重启恢复/登出三项仍按本节 5/6/7 项操作，只是入口变了。

- [ ] 主屏顶部大字显示姓名（无姓名时显示用户名），下方「用户名」字段显示登录用户名
- [ ] 「服务器」字段显示登录服务器 URL
- [ ] 连接状态文本显示「在线」（离线时「离线」）

**RN 对照点**：RN 版此处已是完整房间列表；M1 原生版是占位屏（仅主体信息），此项**不是缺陷**，见「已知差异」第 6 条引言。

### 4. 房间数据落库核对

登录成功后，校验房间数据已写入本地数据库（8 表：`rooms` / `subscriptions` / `chats` / `messages` / `users` / `settings` / `uploads` / `custom_emojis`）。

```bash
# 1) 列出该应用的数据库文件（登录后应出现 appia_<服务器标识>.db）
adb shell run-as cn.appia.im.debug ls databases/
# 期望看到 appia_prelogin.db（未登录占位库）和 appia_<normalizedServer>.db

# 2) 把库拉到本地（Room 用 WAL，三个文件一起拉，拉之前先杀掉 App 保证落盘）
adb shell am force-stop cn.appia.im.debug
adb exec-out run-as cn.appia.im.debug cat databases/appia_<normalizedServer>.db        > /tmp/appia.db
adb exec-out run-as cn.appia.im.debug cat databases/appia_<normalizedServer>.db-wal    > /tmp/appia.db-wal
adb exec-out run-as cn.appia.im.debug cat databases/appia_<normalizedServer>.db-shm    > /tmp/appia.db-shm

# 3) 本机用 sqlite3 查
sqlite3 /tmp/appia.db "SELECT count(*) FROM rooms;"
sqlite3 /tmp/appia.db "SELECT _id, substr(custom_fields,1,80) FROM rooms LIMIT 5;"
```

（如果本机没有 sqlite3，也可直接看文件体积：登录后 `appia_<server>.db` 应显著大于 `appia_prelogin.db`，即为有数据写入。）

- [ ] 登录后 `databases/` 出现 `appia_<服务器标识>.db`
- [ ] `rooms` 表条数 > 0，且与 RN 版同账号的房间数量一致

**RN 对照点**：RN 版用 WatermelonDB（同名 8 表）；重点比对 `rooms` 条数与 `subscriptions` 条数是否一致（同一账号、同一服务器）。

### 5. 组织切换

- [ ] 主屏点「我的企业」→ 底部弹层列出候选组织（含当前组织）
- [ ] 选另一个组织 → 弹层关闭，主屏刷新为新组织的主体信息，「服务器」字段变为新组织 URL
- [ ] 切换失败场景（可开飞行模式后切换）→ 弹「企业验证失败」Alert

**RN 对照点**：候选列表内容与顺序、切换后主屏数据刷新速度。注意已知差异第 3 条：离线时候选列表最长延迟 15s，RN 是缓存即时显示。

### 6. 杀进程重启恢复

- [ ] 在主屏直接杀掉 App（最近任务划掉，或 `adb shell am force-stop cn.appia.im.debug`）→ 重新打开 → **直接回到主屏**，无需重新登录
- [ ] 重启后「在线/离线」状态能自动恢复

**RN 对照点**：RN 版重启同样直达主屏；比对恢复耗时。

### 7. 登出

- [ ] 主屏点「退出登录」→ 回到企业码页
- [ ] 再次登录同一账号 → 正常进主屏

**RN 对照点**：登出后落点（RN 同样回企业码页）、登出后重启 App 不应自动恢复会话。

### 8. `auth_session_expired`（服务端踢出，可选）

任选其一触发（均需管理员配合，做不到可跳过本项）：

1. 服务端吊销该账号会话（管理端踢出该用户在线会话）→ App 内触发任意 REST 请求（如下拉刷新/重进主屏）→ 自动登出回企业码页
2. 服务端吊销会话后杀进程重开 → 冷启动 DDP resume 失败 → 自动登出回企业码页
3. 手工使令牌失效（如服务端改密导致旧 token 失效）→ 触发任意请求 → 同上

- [ ] 登录后由服务端踢出会话（或令牌失效后触发任意 REST 请求）→ App 自动登出并回到企业码页

**RN 对照点**：RN 版会 toast 提示后登出；原生 M1 **直接回企业码页、无 toast 提示**（toast 基建 M5 补），属已知差异第 6 条范畴，不是缺陷但请记录实际表现。

1. **复现步骤**：从哪个页面开始、点了什么、输入了什么（精确到第几步可复现）
2. **RN 表现**：（同操作在 RN 版的行为/文案/时序；「RN 也这样」也要写明）
3. **原生表现**：实际看到的行为/文案/时序
4. **截图/录屏**：两侧各一张（`adb shell screencap -p /sdcard/s.png && adb pull /sdcard/s.png`）
5. 环境：设备型号、Android 版本、App 版本号（0.4.0）

示例：

> - 原生表现：点击后主屏立即切换，但连接状态文本 3s 内显示「离线」再变「在线」
> - 截图：attach
> - 环境：Pixel 7 / Android 14 / 0.4.0

## 四、已知差异（对照 RN 版，非缺陷，请勿按缺陷反馈）

1. **登录页语言切换挂件未移植**：原生版跟随系统语言（中文/英文），登录页内切换语言的入口留到 M5 建应用内语言基建时恢复。
2. **区号回落显示时机**：RN 选择后乐观先显 `+86`（返回登录页后再按实际所选项替换）；原生版等从区号页返回到登录页后才显示所选区号。
3. **组织候选列表离线延迟**：RN 弹层先显缓存再异步刷新；原生 M1 等会话就绪后一次加载，离线时最长延迟 15s。M2 改两段式。
4. **CAS enabled 严格布尔**：服务端返回非严格 `true` 时原生按「未启用」处理（fail-closed）；RN 更宽松。现网无该场景。
5. **密码滑块 4xx/5xx 无横幅**：密码模式下滑块验证页遇到 4xx/5xx 不显错误横幅；只有 SMS 底部弹层滑块有错误横幅（对齐 RN 行为差异待 M2 复查）。
6. **RN 的 `VerificationScreen` 未复刻**：该屏在 RN 侧为死路由（screenRegistry 注册后自身无任何入口导航到），原生未复刻，两侧用户均不可见。

另：主屏（Main）在 0.2.0 是占位屏（主体信息 + 我的企业 + 登出）；0.3.0 起已替换为 M2 会话列表——数据是否落库仍可用第二节第 4 项核对。

## 五、密码登录模式的开启方式

密码模式默认**关闭**，SMS 为主模式。如需自测密码登录（含第 5 条已知差异）：

打开 `app/src/main/kotlin/cn/appia/im/feature/login/ui/LoginScreen.kt`，将

```kotlin
internal const val ENABLE_PASSWORD_LOGIN = false
```

改为 `true` 后重新构建安装（`./gradlew :app:assembleDebug`）。该常量只在 debug 构建自测时有意义；改完记得改回 `false` 再提交。

## 六、M2 自测清单（会话列表与聊天，双端对照）

> 前置：先按第二节第 1/2 项完成登录，0.3.0 登录后主屏即**会话列表**。
> 双端 side-by-side：RN 版与原生 `.debug` 用**同一账号、同一服务器**，开测前两侧各下拉刷新一次对齐初始状态。
> 「另一端」指同账号在 RN 版（或网页端）上做操作，观察原生版是否同步。

### 1. 列表三段分组、排序与搜索

- [ ] 列表最多三段：**我的助手**（个人助手会话）→ **待办**（有 todo 的会话）→ **频道**（其余），空段不渲染段头
- [ ] 段内排序四分支：置顶 > 有草稿 > 未读 > 最后活跃时间倒序；未读分支细节——单方有未读则该会话在前，双方都有未读时按时间倒序
- [ ] 待办段内再四分：高优+草稿 > 高优 > 普通+草稿 > 普通
- [ ] ~~顶部搜索框输入关键字（大小写不敏感）→ 只剩名称/讨论组名匹配的会话；清空后恢复全量~~ **【M5 后测】0.3.0 顶部搜索为不可点击占位（全局搜索属 M5 域），本条随 M5 一并验收**

**RN 对照点**：同账号两侧整屏截屏对比分段与顺序；对同一会话依次「置顶 → 写草稿 → 产生未读」再逐一撤销，两侧排序应逐步同步变化。

### 2. 未读徽标

- [ ] 另一端发消息 → 该行徽标数字 +1，标题加粗
- [ ] 未读 >9 徽标加宽、>99 显示 `99+`
- [ ] 「隐藏未读/免打扰」会话不显示徽标、不参与未读排序（但仍按时间序排列）

**RN 对照点**：徽标数字、宽度三档（16/24/28）、`99+` 文案、标题加粗条件（有提醒且未隐藏未读）。

### 3. 左滑 / 右滑快捷动作

- [ ] 已读态行**右滑**：露出「未读」「置顶（或取消置顶）」两个钮
- [ ] 未读态行**左滑**：露出「已读」钮；此时右滑无可露钮（行拖不动）
- [ ] 每次操作后徽标/排序即时变化；杀进程重开 App 后仍保持（已落库）

**RN 对照点**：按钮文案（未读/已读/置顶/取消置顶）、出现方向与底色、操作后排序位次变化时序。

### 4. 连接横幅与下拉刷新（飞行模式）

- [ ] 列表页开飞行模式 → 数秒内顶部出现断线横幅；关飞行模式恢复网络 → 横幅自动消失
- [ ] 断网状态下拉刷新 → 只弹「同步失败」Alert，**不**出现横幅（已知差异 M2-1）
- [ ] 联网状态下拉刷新 → 同步成功，另一端做的退群/新消息/未读变化反映到列表

**RN 对照点**：横幅出现/消失时机、文案与颜色；刷新后列表变化的字段范围。

### 5. 进房即读 + 停留标读

- [ ] 点开未读会话 → 徽标立即清零（进房即读）
- [ ] 停留在房间内收到新消息 → 约 1 秒后自动标读，退回列表不积累未读
- [ ] 进房后立刻退回（新消息到达 1 秒内离开）→ 该消息仍计为未读

**RN 对照点**：清零时机（进房瞬间）、停留防抖表现、立刻退出时未读是否残留。

### 6. 文本收发（echo 不双条 / 状态徽标）

- [ ] 自己发一条消息 → 只显示**一条**（服务器回执不重复上屏），气泡浅蓝；对方消息气泡主题底色
- [ ] 发送瞬间气泡旁有发送中菊花 → 成功后消失；断网发送 → 出现红色失败角标
- [ ] 对方实时回消息 → 不刷新即上屏；双方连续互发 3 条以上，确认无重复、无丢失、顺序一致

**RN 对照点**：气泡颜色、状态徽标形态与出现/消失时机、echo 去重（重点：每条消息两侧都只出现一次）。

### 7. 历史翻页

- [ ] 进房显示最近一页消息；向上滚到顶部自动加载更早消息，可连续翻到本房最早一条
- [ ] 翻到最早一条后继续上滚不再发起加载
- [ ] 翻页后向上翻页区域出现右下角「↓」按钮，点击回到底部后按钮消失（已知差异 M2-2）

**RN 对照点**：每页条数、加载时机、翻页时列表位置是否跳动。

### 8. 草稿

- [ ] 房间内输入文字不发送 → 返回列表 → 该行第二行显示 `[草稿]` 前缀，且该会话排序升到「置顶之后、未读之前」的草稿优先位
- [ ] 重进房间草稿内容还在；清空输入再返回 → 预览与排序恢复
- [ ] 两个房间各留草稿 → 两条会话都居草稿位，彼此按时间倒序

**RN 对照点**：`[草稿]` 前缀文案与颜色、排序位次、重进保留。两侧均为防抖保存——「输入后立刻杀进程」可能丢最后约 1 秒的草稿，RN 同，不算缺陷。

### 9. 会话消失（removed）

- [ ] 用另一端把自己移出某频道 → 原生列表该会话消失（先等实时推送，再下拉刷新兜底验证）
- [ ] 杀进程重开后该会话仍不出现

**RN 对照点**：消失时机（实时 vs 刷新后）、重开持久性。

### 10. 房间杂项（预览/系统消息/提及）

- [ ] 最后一条消息为特殊类型（图片/文件/联系人等）→ 列表预览文案与 RN 一致
- [ ] 系统消息（成员变更、改公告等）在房间内居中灰字显示，文案与 RN 一致
- [ ] 富文本消息里的 @提及 高亮；纯文本敲的 `@xx` 不高亮（已知差异 M2-3，RN 同款语义）
- [ ] 已读回执（谁读到我这条）原生不显示（已知差异 M2-4）

**RN 对照点**：特殊消息预览文案表逐条对照、系统消息文案、@提及 高亮色。

## 七、M2 已知差异（对照 RN 版，非缺陷，请勿按缺陷反馈）

> M3 后已收口的条目标注【M3 已收】：2（未读横幅）、3 后半（MENTION 显示名解析）、4（已读回执）、7（未读横幅）、8（附件/富文本/回复引用/撤回）。其余条目仍有效。

1. **下拉刷新失败仅 Alert，不触发断线横幅**：横幅由连接层（DDP phase）驱动，断线判定收敛在 M5 收口。
2. **滚到底按钮简化为「不在顶部即显示」**：~~RN 的未读跳转横幅形态属 M3~~【M3 已收——`room.firsUnread`「N 条新消息」横幅已实现（≥10 条时显示，点击跳转目标消息）】。
3. **mention 高亮仅 md AST 来源**（纯文本 @xx 不高亮，RN 同款语义）；~~MENTION 显示名解析简化（显示 @username，M3 接入 MarkdownContext 后按昵称解析）~~【M3 已收——mentions 数组命中显示 name（无 @），未命中 @username；@all/@here 群色、提及自己高亮色】。
4. ~~**已读回执不渲染**（M3 补）~~【M3 已收——自己消息可点已读/未读图标进明细页；DM 房不渲染可点图标（RN 同款绑定）】。

## 八、M3 自测清单（富文本消息，双端对照）

> 前置：按第二节完成登录；双端同账号同服务器 side-by-side。
> 编辑器为 WebView 富文本（工具栏 Aa 展开），发送后消息以富文本渲染——两侧对照重点在**渲染一致性**与**编辑操作对称性**。

### 1. 富文本编辑与发送

- [ ] 输入区点 **Aa** 展开工具栏：加粗/斜体/删除线/高亮/字色（11 色含默认）/有序列表/无序列表/清除格式；再次点 Aa 收起
- [ ] 选中文字后点加粗 → 发送 → 消息加粗显示；斜体/删除线/高亮/字色同法逐项验证
- [ ] 工具栏按钮的「激活态」（当前光标处已加粗时加粗钮高亮）随输入位置变化正确回读
- [ ] 发送标题（Heading）、有序列表（`1.` `a)` `i)` 层级）、无序列表（嵌套缩进）、引用块、代码块——双端渲染一致
- [ ] 发送带链接的文字 → 双端可点、颜色一致

**RN 对照点**：工具栏按钮集合与顺序、激活态回读、各格式渲染样式（字号/颜色/缩进/marker 形态）。

### 2. 富文本渲染（对侧发来的消息）

- [ ] RN 版发送富文本（标题/列表/代码块/引用/表格/链接）→ 原生版渲染一致
- [ ] **表格**：消息内表格显示 3 行截断预览，点击展开全屏横滚表格，关闭按钮可退
- [ ] **代码块**：AI 消息代码块带语言标签与复制按钮，复制到剪贴板内容正确
- [ ] **BIG_EMOJI**：纯 emoji 消息（如 `😀😀`）布局特判与 RN 一致
- [ ] **mention 色**：@提及 命中成员显示昵称（无 @ 前缀）+ 高亮色；@all/@here 群色；提及自己用 mentionMe 色
- [ ] **KaTeX 公式**：行内/块级公式显示原式等宽文本，**点击打开全屏 WebView 渲染**（已知差异 M3-1——RN 直接行内渲染）
- [ ] **(edited) 标记**：被编辑过的消息尾部显示 `(edited)` 灰字，位置与 RN 一致（列表结尾/引用内等边角）

**RN 对照点**：逐类截图对比；表格截断行数、代码块复制入口、emoji 表情（含 `:zap:` 等自定义 shortname）渲染。

### 3. 附件收发与查看

- [ ] 点 **+** → 照片/文件选择器 → 选图发送 → 双端显示图片消息；点开全屏查看（双击 2x 放大、捏合缩放 4x 上限）
- [ ] 发视频 → 双端可播（原生 Media3 播放器，标题栏文件名）；发音频 → 可播
- [ ] 发文档（PDF）→ 点开预览分页渲染；office 文档（白名单类型）→ 服务端转码轮询后预览
- [ ] 上传中大附件 → 气泡旁**圆形进度环**（非菊花）；上传失败 → 红色失败角标 + 重试可点
- [ ] 一次选超过上限数量附件 → toast 提示实际接受数
- [ ] 收到对侧发的图片/视频/文档 → 双端渲染与查看入口一致

**RN 对照点**：上传进度形态、图片缩放手势、PDF 渲染清晰度、附件容量上限与提示文案。已知差异：图片**无客户端压缩**（跟随 RN 现状，picker quality 之外零处理）。

### 4. 转发（单条 + 合并）

- [ ] 长按消息 → 转发 → 选 1 个或多个目标（DM/群，上限 10）→ 确认发送 → 目标会话收到
- [ ] 多选模式 → 逐条转发 / **合并转发** → 目标会话显示「甲和乙的聊天记录」卡片（标题四分支：两人/多人/房间名/兜底）
- [ ] 点合并转发卡片 → 详情页逐条渲染（含日期分隔），内层再遇合并卡片可继续下钻
- [ ] 转发选择页搜索（300ms 防抖）→ 过滤 DM/群

**RN 对照点**：卡片标题文案、前 2 条预览、页脚样式、详情页日期分隔。

### 5. 表情回应（Android 领先功能）

- [ ] 消息反应条点 **＋** → 选 emoji → 反应条显示该 emoji + 计数 1；再点同 emoji → 撤回（计数归零消失）
- [ ] 对侧（RN 版）**看不到**该反应——**预期行为**（RN 未实现表情回应，Android 领先；服务端已持久化，RN 被动数据不冲突）
- [ ] 空反应条也显示 ＋ 入口；点已有反应 chip 同样 toggle

**RN 对照点**：无（RN 0 字节占位）——本项只验证原生侧功能正确与服务端持久化（换设备重进反应仍在）。

### 6. 已读回执

- [ ] 自己发的消息（频道）→ 消息旁已读/未读图标（未读蓝色）→ 点击进明细页 → 已读/未读 tab 列出成员
- [ ] 对侧读了消息 → 图标变已读；明细页成员移动到已读 tab
- [ ] DM 房不显示可点图标（RN 同款绑定）；发送中/失败的消息不显示回执图标

**RN 对照点**：图标形态与颜色、明细页 tab 结构、DM 行为。已知差异：回执为服务端单布尔（无三态勾，RN 同）。

### 7. 编辑 / 撤回 / 重新编辑

- [ ] 长按自己消息 → 编辑 → 输入区出现编辑横幅（✕ 可退出）→ 修改后发送 → 消息更新 + `(edited)` 标记
- [ ] 编辑带富文本的消息 → 工具栏回填原格式（加粗等保持）
- [ ] 长按自己消息 → 撤回 → 消息变为「已撤回」分组显示；**长按撤回消息 → 重新编辑 → 原文回填输入区**（快照恢复）
- [ ] 多选 → 批量撤回 → 确认后全部撤回（失败则保持多选可重试）
- [ ] 对侧撤回的消息 → 原生显示「撤回了一条消息」系统样式

**RN 对照点**：编辑横幅形态、(edited) 位置、撤回分组文案、重新编辑回填完整性（富文本/mention 复位）。

### 8. @提及补全

- [ ] 输入 **@** → 弹出成员建议列表（多选，底栏 Done）；选中 → 输入区插入 mention（高亮）
- [ ] 工具栏 @ 按钮（DM 房不显示该按钮——预期）→ 直达建议列表
- [ ] 发送后 mention 渲染为昵称 + 高亮色；对侧收到同样渲染
- [ ] agent/AI 房 bot 候选暂为空集（M4 联系人域后补——已知差异 M3-8）

**RN 对照点**：建议列表触发时机与防抖、插入形态、mention 渲染色。

### 9. 长按菜单全集

- [ ] 长按自己消息：回复/编辑/复制/转发/多选/撤回/重发（失败消息）
- [ ] 长按他人消息：回复/复制/转发/多选（无编辑/撤回）
- [ ] 只读房长按无菜单
- [ ] 回复 → 输入区带引用前缀 → 发送 → 消息带引用块渲染

**RN 对照点**：菜单项集合与判定条件（长按时长原生 400ms 系统默认 vs RN 500ms——已知差异 M3-9）。

## 九、M3 已知差异（对照 RN 版，非缺陷，请勿按缺陷反馈）

1. **KaTeX 公式降级原式文本**：行内/块级公式不直接渲染为排版公式，显示原式等宽文本，**点击打开全屏 WebView 渲染**（低频场景首版降级；RN 行内直接渲染）。
2. **表情回应 Android 领先**：RN 版未实现（0 字节占位）——原生侧的反应在 RN 端**不可见**，属预期；服务端 `chat.react` 已持久化，两侧数据不冲突。反应条自定义 emoji 回退 `:code:` 文本（标准表外），picker 为固定 12 常用集（legacy 全量+搜索后补）。
3. **图片无客户端压缩**：跟随 RN 现状（picker quality 0.8 之外零处理），大图直传；Coil 磁盘缓存承担大图查看（RN 的 200MB trim / SubsamplingScaleImageView 不做对等）。
4. **附件卡片 ACTIONS / COLLAPSIBLE_QUOTE 不渲染**：bot/集成卡片消息（按钮行/可折叠卡片）Android 侧暂不显示，推迟 M7 交互消息域（QUOTE 引用卡片 RN 亦不渲染，忠实一致）。
5. **相册 Pager 范围 = 本消息图片**：RN 的全房间媒体画廊（跨消息浏览）未移植，推迟 M7 画廊专项；点开图片只在同消息图片间翻页。
6. **PDF 整本一次性渲染**：大几百页 PDF 会慢/占内存（PdfRenderer 自绘天花板），首次卡顿/OOM 反馈时升级按页懒渲染。
7. **office 预览依赖服务端转码轮询**：白名单类型走 DocPreview 轮询（31 次 × 2s 上限），转码失败显示错误态；RN 的 `localFile` 直开路径不移植（Android 附件链无本地路径参数）。
8. **@提及 bot/agent 候选为空集**：AI 房 bot 候选依赖 M4 联系人域（settings 表 M5 拉齐前为空集）；成员建议行头像暂用首字母圆点（成员头像 URL 组装 M4 补）。
9. **长按时长 400ms**（Android 系统默认）vs RN 500ms；长按菜单图标未转录（纯文字项）。
10. **编辑横幅简化**：标题+✕（RN EditPreview 另有原文预览行）；编辑提交分路——纯文本走 updateMessage、带文件恒走 replace（RN 恒 replace，服务端效果一致）。
11. **转发选择页组织树 tab 降级**：PMT/L1D tab 现出最近会话占位，M4 联系人域后补树形+部门多选。
12. **合并转发卡片视觉为 M3 简化**：圆角/涟漪等未逐属性像素级复刻（间距字号按 RN styles 值对齐），验收走查若要求像素级再调。
13. **AI 摘要 / 横竖屏切换 / 全房间画廊**（附件查看器附属功能）未移植，接受推迟。
14. **ChatList 列表预览 mention 显示名**：列表第二行预览中 mention 仍显示 @username（正文渲染已按昵称解析），M4 联系人/成员域一并收口。
