### 1.4 推送 payload 形态

ejson 业务体（`RN/src/services/notification/pushTypes.ts:13-30`）：

```
{ rid, name, sender:{username,name}, type: 'c'|'d'|'p'|'l', host,
  messageType, messageId, msgType?, oncall?, recordId?, channelId?,
  org?, callMsg?, isCallEnd? }
```

事件到达形态分层兜底（`RN/src/services/notification/extractPushEjsonPayload.ts:104-167`，优先级从上到下）：

1. `raw.ejson`（iOS / 部分到达事件，JSON 字符串）；
2. `raw.extra` / `raw.extras`（JSON 字符串袋）内的 `ejson` —— **Android 点击通知的实际形态**：`{title, summary, extra: '{"ejson":"{...}"}'}`（:96-103 注释 + 桥 `AliyunPushEventEmitter.kt:193-199` 只透传 `extra` 字符串）；
3. `extra` 整袋即业务体（:127-128）；
4. 顶层 `rid+type` 直挂（:134-136）；
5. 仅 `rid` → type 兜底 `'c'`（厂商通道丢 type 场景，:143-157）；
6. 仅顶层 `roomId + msgType='oncall'`（语音最小体，:159-164）。

到达事件与点击事件的 JS 分发（`pushService.ts`）：

| 事件 | 监听 | 行为 |
|---|---|---|
| `onNotification`（到达，iOS 含前台；Android 后台/被杀） | `addNotificationCallback` :122-128 | **Android 前台直接 return**；其余走语音分流 + 跨组织未读刷新 |
| `onNotificationOpened` / `onNotificationClickedWithNoAction`（点击） | :130-132 | `handleNotificationOpen`（见 §2） |
| `onNotificationReceivedInApp`（仅 Android 前台） | :135-138 | 语音分流 + 跨组织未读刷新，**无应用内横幅** |
| `onMessage`（透传） | :141-144 | 同上 |

**前台/后台展示**：通知由阿里云 SDK 自身投递到系统栏（进程存活走自建长连接 + `channel_01`；被杀时厂商通道/FCM 系统投递）。RN 层从不自绘通知。服务端决定是否推送（房间 mute 等是服务端策略，客户端无展示时静音门控——全 src grep 无本地 mute 检查）。

**进程被杀后的点击**：SDK 拉起 App，`onNotificationOpened` 经 `AliyunPushEventEmitter` **缓存事件（每类型最多 10 条）直到 JS 挂上监听**（`AliyunPushEventEmitter.kt:91-136`），不丢。

## 2. 深链导航

### 2.1 URL scheme：声明了但 RN 侧无消费者

`RN/AndroidManifest.xml:83-113` 的 MainActivity intent-filter 声明了 `appia://room|auth|fse`、`https://(pre|sophgo|ssc).appia.cn|appia.cn`、`wemeet://wemeet`——但 **RN src 全库无 `Linking.getInitialURL` / `Linking.addEventListener('url')` 消费者**（grep 仅命中出站 `openURL/openSettings`）。MainActivity.kt 亦无 onNewIntent/深链处理。这组 filter 是旧版遗留死配置。**推送点击进房完全不走 URL scheme**，走 SDK 回调→JS 事件→导航队列。

### 2.2 推送点击 → 房间的精确路径

`pushNavigation.ts`（`RN/src/services/notification/pushNavigation.ts`）：

1. `handleNotificationOpen(raw)` :241-277 → `parsePushPayload` :125-148：ejson 提取（§1.4）→ `ROOM_TYPE_MAP {c:channel,d:direct,p:group,l:omnichannel}` :24-29 → 标题 `resolvePushRoomTitle`（d 取 sender.username；l 取 sender.name ?? name；其余取 name）:39-49 → 参数 `{rid, t, title, messageId, host, isCall, voiceOncall}`。**`messageId` 即 ejson 的 messageId，后续映射为 `jumpToMessageId`**。
2. **host 校验**：`isPushHostMatchingCurrentServer(pushHost, currentServer)` :166-176（比 hostname、忽略协议/尾斜杠/子域后缀）；不匹配 → 跳过进房（多组织防护）:252-260。
3. 语音 oncall 意图 → `routeToVoiceSession`（M10 域，M6 可忽略）:262-265。
4. `dispatchRoomNavigation` :203-219：先 `minimizeActiveVoiceCallForRoomNavigation`（通话中最小化不打断）:182-192，再 `navigateToRoomFromAppRoot(ref, {rid, t, title, jumpToMessageId: messageId})`。
5. `navigateToRoomFromAppRoot`（`RN/src/lib/chat/navigateToRoom.ts:105-149`）：优先对已挂载 Chat stack 以 `target` dispatch `reset([MineDrawer, Room(params)])`（复用 MineDrawer key 防列表重建）；Chat 未挂载则 nested navigate；最后兜底 root reset。
6. **未就绪排队**：导航 ref 不存在或未登录 → `enqueueRoomPushNavigation`（`roomPushNavigationQueue.ts`：内存队列、**TTL 90 秒** :11、按 `rid:messageId` 去重 :18-19）。
7. **drain 触发点（三处）**：NavigationContainer `onReady`（`RootNavigator.tsx:53-56`，须已登录）；MainNavigator 挂载（`MainNavigator.tsx:38-40`）；AppState 回 active + **400ms 延迟二次 drain**（`MainNavigator.tsx:62-72`，同点还 `removeAllNotifications()` :64）。`drainPendingRoomPushNavigations` 门控 `isAuthenticated && navRef`（`pushNavigation.ts:178-179,225-232`）。

### 2.3 冷启动 vs 热启动语义

- **冷启动（进程被杀）**：SDK 拉起 App → 事件被桥缓存 → JS 监听挂上后补发 → `handleNotificationOpen` 时导航未就绪 → 入队 → RootNavigator onReady / Main 挂载时 drain。登录态缺失时队列等待（90s 内登录完成则跳，否则丢弃——RN 无「登录后强制续跳」逻辑，drain 门控即全部）。
- **热启动/前台**：同一路径，通常导航已就绪即时跳。
- **消息高亮**：`jumpToMessageId` 进 Room 参数即触发 M5 已建的跳转管线（RN RoomView useEffect；AA 侧 `RoomRoute.jumpToMessageId` + `MessageJumpController`，见 §4）。

### 2.4 AA 侧衔接点（现状）

- `AA/.../MainActivity.kt:186-201` `RoomRoute(rid, title, roomType, jumpToMessageId, fromGlobalSearch)` 已具备；jump LaunchedEffect :663-667；`onCrossRoomJump` :849-858 注释明写「M6 深链同径」。MainActivity 目前无 onCreate intent / onNewIntent 处理，无 pending-intent 队列。

## 6. 坑清单（按危害排序）

1. **双初始化返回码**：JS `initPush` 在原生 bootstrap 先行时返回 `PUSH_20110`；若按非 10000 失败提前 return，**点击通知的监听器永不注册、推送点击无法进房**（`pushService.ts:56-63` 注释原话）。
2. **原生必须 Application.onCreate 初始化**：推送冷拉起进程不执行 JS（Android 原生重写后此坑自动消解——AA 只有一套原生；但注意 AA 无隐私同意流程，RN 是同意后才 init）。
3. **`channel_01` 必须预建 IMPORTANCE_HIGH**：阿里云 payload 默认通道，不预建则系统自动低重要性建 → 进程存活时无横幅/声/震（`VoiceNotificationChannels.kt:14-23`）；且 Android 不允许覆盖已存在通道重要性，老用户升级可能永久无声（foreground-fix plan Step 5 已知限制）。服务端可切 `im_default` 为备选（plan 注释）。
4. **POST_NOTIFICATIONS 无运行时申请**（RN manifest:46 仅声明，全库无 request）——Android 13+ 默认拒绝时通知静默消失。AA 应补运行时申请（故意分歧点）。
5. **payload 形态四层兜底**：Android `extra` 双重转义 JSON 字符串、厂商通道丢 type、裸 rid、oncall 最小体——解析必须移植 `extractPushEjsonPayload` 全部兜底层，否则特定通道点击进不了房（:118-164）。
6. **host 不匹配静默跳过**：多组织下他服推送点击不得进房（`pushNavigation.ts:252-260`）；AA 每组织独立 db/serverUrl，需等价校验。
7. **冷启动导航队列 90s TTL + rid:messageId 去重 + 三处 drain（onReady / Main 挂载 / 回前台+400ms 延迟）**：漏任一 drain 点都会「点击通知 App 起来了但没进房」（`roomPushNavigationQueue.ts:11-19`、`MainNavigator.tsx:62-72`）。
8. **messageId ↔ jumpToMessageId 同径**：高亮走 M5 管线即可，但 ejson 无 messageId 时只进房不高亮（`pushNavigation.ts:134-137` 容忍 undefined）。
9. **FCM/google-services 与 `.debug` 后缀冲突**：AA debug applicationId=`cn.appia.im.debug` 与 google-services.json（package `cn.appia.im`）不匹配，GMS 机型离线推送（FCM 辅助通道）会因此缺失（fcm-push plan Task1 STOP 条款）。
10. **versionCode 下限**：正式包必须 > 28187853（生产版已装），否则自更新下载后系统安装器拒装；RN ABI 拆分方案（abi*2^20+base）可照搬（RN build.gradle:176-186）。
11. **自更新「暂不升级」是会话内静默（内存 ref，非持久化）**：冷启动重弹是 2026-09-15 有意修订；手动「检查更新」`bypassDismiss` 覆盖静默（`AppUpdatePromptHost.tsx:55-56,80-91`、plan §6.4）。勿"修复"成持久化。
12. **强制更新无返回键出口**：`onRequestClose` 仅非强制时给（`AppUpdateModal:83`）；下载中隐藏两个按钮只留进度条。
13. **APK 安装链**：App 专属外部目录 Download（免权限）+ FileProvider content URI + `REQUEST_INSTALL_PACKAGES`；`fileHash` 客户端未校验（不校验是 RN 现状）；无断点续传；已装同版本 APK 直接复用跳过下载（`appReleaseInstaller.ts:51-54`）。
14. **电池优化白名单引导**：杀进程后推送到达依赖厂商白名单（REQUEST_IGNORE_BATTERY_OPTIMIZATIONS + 引导弹窗，冷启动+登录双触发）；AA 有权限无引导逻辑。
15. **RN manifest `appia://` intent-filter 是死配置**：勿照抄为 M6 方案依据；AA 深链用 intent extras 自建即可（若要保 scheme 兼容旧二维码/外部链接，另立任务验证消费方）。
16. **回前台清理通知**：AppState active 时 `removeAllNotifications()`（`MainNavigator.tsx:64`）——进房已读后通知栏残留需清。
