# M8 T1 RTC token spike 结论（2026-10-10）

> 目的：裁定 M8 Open Question 1——原生会议入会的 Agora appId/token 从哪来。**结论直接决定 T6/T7 形态。**

## 结论：**B（高置信）** —— 存在独立凭据接口，IM 会话 token 直接可用

AntMeeting H5 的 bundle 静态分析显示，其入会凭据来自 H5 自有后端的 credentials 接口族，
鉴权头是 **IM 用户现有会话 token**（`X-Auth-Token` = Rocket.Chat loginToken）——AA 登录后已持有。
**唯一未闭合项**：credentials 响应体的确切字段名（appId/token/uid 推定自 join 消费侧）需按 §4
流程抓包确认（用户域，一次即可）。

## 1. 方法

1. RN 静态分析：meeting 域代码找 appId/token 处理（`appiaMobile`）。
2. AntMeeting H5 bundle 静态分析：抓 `https://meeting.appia.cn/AntMeeting/` 壳页 →
   下载 `index-BsNUgxgl.js`（1.2MB）与 `meetingUtils-DCAhqmIV.js`（14KB）反混淆关键路径
   （公开静态资源，非端点探测）。
3. 服务端探测：10 个候选路径 GET，无凭据（清单见 §3）。

## 2. 证据

### 2.1 RN 侧（会议域零 Agora 参与）

- `src/services/api/meeting.ts`：`meetingRoomBook` 返回类型仅为 `{ success?, message? }`——
  响应体若有额外字段（含潜在凭据）RN 一律丢弃。6 个 meeting 接口均如此。
- `MeetingFormScreen`/`RoomMeetingScreen`/`lib/meeting/*` grep 无任何 agora/appId/token 消费；
  唯一 token 字样是 `antMeetingUrl.ts` 的外部授权码 `?code=`（RN 调用方已弃用，
  `openAntMeetingWeb.ts:23` 注释明示）。RN 会议 RTC 全在 H5 内（Agora Web SDK）。
- RN wire 是 Rocket.Chat 式（DDP `meetingRoomBook` + REST `/api/v1/*`），无 meeting 专用 token 接口。

### 2.2 H5 bundle 侧（决定性证据）

`meetingUtils-DCAhqmIV.js`：

```js
const K = "/api/v1/video/meeting",
      be = "/api/v2/video/meeting",
      Ne = "https://meeting-server.appia.vip";   // 独立会议服务端（可配置覆盖）
```

`index-BsNUgxgl.js`（API 客户端）：

```js
getCredentials:   (t,e,r=false) => `${meetingApiUrl()}/${t}/credentials?uid=${e}&encrypted=${r}`
getCredentialsV1: (t,e) => `${meetingApiUrl()}/credentials?channelName=${...}&uid=${e}`
getCredentialsV2: (t,e) => `${resolveMeetingApiV2Url()}/credentials?channelName=${...}&uid=${e}`
```

- 请求头：`X-Auth-Token: <IM loginToken>`（`Meteor.loginToken`，localStorage 恢复）+
  `X-Client-Platform: mobile`。**即 IM 会话 token 直连会议服务端，无需单独换发。**
- API base 解析链：登录响应 `appia_domain`/`meeting_api_origin` 覆盖 → 默认同源
  `${serverUrl}` → 兜底 `https://meeting-server.appia.vip`（`Le()` 判 `appia.cn|vip` 域）。
- 同族还有 `{id}/end`(POST)、`{id}`(DELETE)、`{id}/participants/export`——会议服务端自成一家。
- 独立登录流 `client-auth/login`（传 `appiaUserId`+`appiaToken` 换 `clientToken`）仅
  Electron/独立浏览器用；App 内 WebView 走 X-Auth-Token。
- **SDK 级无证书回退**：Agora Web SDK join 门槛 `a.token===this.context.appId&&(u=void 0)`
  ——token 缺省/等于 appId 时按无 token 入会（App Certificate 未启用模式），SDK 原生支持。

### 2.3 服务端探测（10 请求，无凭据）

| 请求 | 结果 |
|---|---|
| `appia.cn/{rtc/token, api/v1/rtc/token, api/v1/agora/token, agora/token, meeting/token, api/v1/meeting/token}` | 均 200 = Meteor SPA 壳（222KB HTML），`/api/v1` 路径返 HTML 壳即**非 REST 路由**（真路由返 JSON）——6 路径均不存在 |
| `meeting.appia.cn/`、`/rtc/token`、`/api/token` | nginx 404——该 host 只挂 `/AntMeeting/` |
| `meeting.appia.cn/AntMeeting/` | 200 = Vite H5 壳（bundle 名即 §2.2 来源） |

推断：凭据接口不在 IM 主站路径下，与 H5 证据一致（独立 meeting-server / 同源 `/api/v1|v2/video/meeting`）。

## 3. 结论对照（plan 三选一）

- ~~A：meetingRoomBook 返回体含凭据~~ —— 否。RN 不消费 + H5 自有凭据接口，无关联证据。
- **B：有独立 token 接口 —— 成立**（见 §2.2）。✅
- ~~C：无接口 → 无 token 模式~~ —— 不需要作为主方案；但 SDK 级 cert-less 回退真实存在
  （§2.2 末条），可作 T6 开发期兜底。

**B 附带条件**：响应体字段名未实抓（appId/token/uid 为 join 消费侧反推）。按 §4 流程抓一次闭合。

## 4. 用户抓包流程（验收协议级，一次即可闭合）

前置：模拟器或真机 + 测试账号（能登录、能在某房间建会）；Charles/mitmproxy 已装好 HTTPS 证书。

1. 启动抓包，过滤 host：`appia.cn`、`appia.vip`（重点 `meeting-server.appia.vip`）。
2. AA（或 RN 版）登录测试账号 —— 记录登录响应里的 token 字段名与值格式。
3. 进入任意房间 → 附件「会议」→ 新建会议（任意主题，立即开始）→ 提交。
4. 提交成功后**立即进入会议**（H5/原生发起 join）——此时抓：
   `GET {meeting-server}/api/v1/video/meeting/credentials?...`（或 v2、或 `/{id}/credentials`）。
5. 导出该请求的：完整 URL、请求头（`X-Auth-Token` 值可打码，只需确认=登录 token）、
   **响应体全字段 JSON**（预期含 appId、token、uid；记录确切字段名与 token 形态
   ——Agora AccessToken 形如 `007...eAEA...`，或空/等于 appId 则为 cert-less 模式）。
6. 顺带记录：会议创建接口 `meetingRoomBook` 的**响应体全字段**（验证是否真无凭据字段，
   闭合结论 A 的排除）。

若第 4 步抓不到 credentials 请求：说明会议服务端域不同——抓包里找 `/video/meeting/` 字样
的任意 host，同格式导出即可。

## 5. T7/T6 建议（形态）

1. T6 引擎封装：appId+token 经 wire 层新接口取——`GET {meetingServer}/api/v2/video/meeting/credentials?channelName={ch}&uid={uid}`
   （v2 优先，v1 兼容），鉴权 `X-Auth-Token`。base 解析照抄：登录响应 `appia_domain` 覆盖 →
   同源 → `https://meeting-server.appia.vip` 兜底。
2. 兜底链：credentials 获取失败或 token 为空/等于 appId → SDK cert-less 模式直接 join
   （开发期测试服务器大概率未启用 App Certificate，先按此打通，抓包后再收紧）。
3. A 组排除已成立，无需对 meetingRoomBook 响应做任何凭据假设；T2 wire 层按
   `{success?, message?}` 建模即可。
4. 待 §4 抓包回填：确切字段名 / v1-vs-v2 实际使用 / meeting-server 实际域名。
